## Part 2 — `build_bib.py` and its tests

| Area | Verdict | Evidence / review |
|---|---|---|
| Venue → BibTeX type mapping | **DISAGREE: one concrete misclassification.** The heuristic at `scripts/build_bib.py:22-25,39-44` maps journal names only when they contain a hard-coded keyword. Registry record `chen2026scope` is in *Journal of Imaging* (`literature/sources.yaml:683-694`) but “Imaging” contains none of those triggers, so it becomes `@inproceedings` with `booktitle`; it should be `@article` with `journal`. The enumeration command over all registry venues yielded this sole non-conference false negative. Conference/workshop entries, arXiv/null venues and TMLR/IEEE transaction venues otherwise map to their expected types in the current registry. |
| Escaping | **DISAGREE: incomplete BibTeX escaping / tests.** `_esc` (`scripts/build_bib.py:29-30`) covers `&`, `%`, and `#`, but leaves BibTeX-special `_`, `$`, `{}`, `^`, and `~` unhandled in title/venue text; author strings are inserted without `_esc` at line 47. Existing test covers only `&` in a title. Add representative special-character cases before relying on arbitrary future registry text. Current source title/author/venue scan found no such characters, so this is latent input risk rather than a demonstrated current refs.bib failure. |
| Citation macro parsing | **AGREE for requested macros and arguments; DISAGREE on comment handling/test gap.** Regex `scripts/build_bib.py:21` accepts `\\citet`, `\\citep`, `\\citealp`, `\\citeauthor`, stars, up to two optional bracket arguments, and comma-separated keys. A direct scratch check returned keys from `\\citet[see][p. 3]{a,b}`, `\\citep*{c}`, `\\citealp{x}`, and `\\citeauthor{d}`. It also returned `commented` from a `% \\cite{commented}` line: TeX comments are not stripped, causing false missing-citation failures. Neither requested macro coverage nor comments are fully exercised by `tests/unit/test_build_bib.py:21-27`. |
| `--check` semantics | **AGREE with the implemented/documented meaning, with a caveat.** `main` always writes `paper/survey/refs.bib` before checking keys (`scripts/build_bib.py:96-100`); `--check` additionally reports cited unverified records and fails for missing keys, as documented. It does not compare the generated bibliography against a checked-in file or act as a non-mutating freshness check. The current docs describe generation plus citation-key validation, so this is not a code defect, but the command can overwrite local bibliography edits and should not be mistaken for a read-only check. |
| Test adequacy | **DISAGREE: too narrow for the asked surface.** Two tests (`tests/unit/test_build_bib.py:7-27`) cover conference/article/preprint examples, ampersand escaping, basic `citet`/`citep` optional-argument and multiple-key handling, and helper return values. They omit the actual `Journal of Imaging` venue, other BibTeX-special characters/authors, `citealp`/`citeauthor`/stars, TeX comments, duplicate IDs, and CLI write/check exit behavior. Manual coverage above found the comment false positive. |
